# 社区优化实施计划

> 本文是跨工作流的规划，不是功能承诺。涉及行为变更的工作，在实施前分别确定方案、测试和兼容性策略；不自动提交或发布。

**目标：** 在不牺牲安全边界和兼容性的前提下，降低首次使用成本，提高可验证的可靠性和社区可发现性。

**方法：** 先核实当前文档与真实用户体验，再把高频失败变成可复现测试和明确提示；真机证据、上游协作和社区反馈分别记录，避免把单机通过或下载量当成用户成功率。

**技术范围：** DeepSeek Harness、Windows、WSL 2、distro 内 agent、bubblewrap、Node.js、pnpm 和 GitHub Actions。

## 全局约束

- 以当前实现、`cordis.patch.yml` 和 `package.json` 为行为依据；测量注明日期、版本、环境与样本量。
- `src/` 为源码；`lib/` 只能通过 `pnpm run build` 生成。单测针对 `lib/`，提交前运行 `pnpm test`。
- 保持现有默认安全策略；Linux 沙箱对 Windows interop 仅提供部分约束，不把遮罩 `/mnt` 描述为完整隔离。
- 不默认启用遥测；诊断结果或日志须经用户审阅和同意后共享。不要把本机用户名、路径、配置或密钥默认发布。
- 真实 Windows + WSL + Harness 探针与单测、模拟、容器和 QEMU 测试分开记录；跳过不计为通过。
- 工作按独立主题拆分；原 [1.0 路线图](../../ROADMAP-1.0.md) 仍是产品路线与状态的权威入口，本计划用于排序和执行，不复制已完成项为待开发功能。

## 当前基线

- 仓库版本为 `0.15.0`；已有 doctor、安装 E2E、兼容性矩阵、peer canary 和原生 agent。具体状态以实现及各文档的证据日期为准。
- 用户提供的 2026-10-31 真机日志显示完整套件 15 项、0 项失败；它是一次特定环境的结果，不代表跨机器或每个内部检查均已验证。
- 真机 CI 的探针任务在环境缺失时可以跳过；首次安装成功率、干净机器首次成功耗时和实际活跃用户数没有可靠基线。
- 已发现文档时效冲突：根文件系统路由文档称套件为 12 项且没有路由探针，而现行套件包含 `fs-routing.sh`；1.0 路线图仍有旧探针计数和历史状态，需逐项核实。

## 阶段与依赖

以下按一名维护者、每周能投入一部分时间估算；测试用户、Windows 机器和上游反馈不在维护者控制范围内，时间不是交付承诺。

| 阶段 | 参考周期 | 交付结果 | 前置条件 |
|---|---|---|---|
| 1：可信基线 | 第 1–2 周 | 完成全仓文档时效审查；形成首次安装测试方案 | 不依赖新代码 |
| 2：首用与真机证据 | 第 3–6 周 | 获得首用反馈；让真机运行和跳过状态清晰可见 | 首用测试需参与者；自动化需专用 Windows + WSL 环境 |
| 3：可靠性与生态 | 第 7–10 周 | 根据故障频率修复问题；整理上游协作材料和演示 | 阶段 1–2 的实测或独立复现 |
| 4：发布评估 | 第 11–12 周及以后 | 根据证据决定是否发布下一版本或进入 1.0 候选 | 必须满足现有发布门槛，不以日历代替验证 |

阶段可以重叠，但故障修复、CI 变更和默认值变更分别设计、测试与审查。

- [ ] 从用户入口、配置、安全与限制开始，逐项核对命令、默认值、支持范围、路由、示例和链接；再审查设计、计划与历史材料。历史事实保留原日期，用注释或当前说明消除误读，不改写历史。
- [ ] 修正上述探针数量与路由覆盖冲突；核对路线图中“未运行”和未勾选项是当前状态还是历史记录，不能仅按时间猜测结果。
- [ ] 同步中英文入口与配置说明；核对文档地图是否指向正确的权威资料，并明确上游提案不等于已经采纳。

## 工作项 2：测量并改善首次使用（P0）

**涉及：** `README.md`、`docs/QUICKSTART.md`、`docs/CONFIGURATION.md`、`scripts/doctor.mjs`、`scripts/profile-preset.mjs`、`test/doctor.test.mjs`、`test/profile-preset.test.mjs`、`test/e2e/install.sh`。

- [ ] 设计一页测试记录：Windows、WSL、distro、Harness 和插件版本；起止时间；每一步卡点；首次成功命令所在 distro、工作目录和实际沙箱事实；失败或中途退出也计入记录。
- [ ] 邀请 5–10 位未参与开发的用户按公开文档操作；先让参与者独立完成，帮助前记录问题。无参与者时保持此项未完成，不将维护者自己的重复运行冒充独立用户。
- [ ] 优先使用干净 Windows + WSL 环境；若只能使用新建 distro 或临时 `DSH_HOME`，标注它不是干净 Windows 首次安装，不混合为同一类结果。先征得环境所有者同意，不修改既有发行版或用户资料。
- [ ] 按阻塞人数和严重程度排序，先修复真实发生的安装、配置和诊断问题；任何 doctor 行为变更先加对应单测，修改源码后构建，并核对安装包内运行方式。
- [ ] 在受控环境运行既有 `pnpm run e2e:install`，记录其覆盖的安装、升级和卸载范围；它不能替代真人从干净机器首次使用。

**验收：** 有去标识化的原始测试记录、问题清单和复测结果；展示成功数/尝试数与实际耗时。5–10 人仅用于发现问题，不能据此证明成功率达到 95% 或稳健估计 p90。

## 工作项 3：真机回归与发布证据（P0）

**涉及：** `.github/workflows/ci.yml`、`test/probe/run-all-when-closed.sh`、`test/probe/`、`test/probe-runner.test.mjs`、`docs/RELEASING.md`、`docs/COMPATIBILITY.md`。

- [x] 梳理现有调度、前置条件与实际跳过路径，确定哪些探针需要 Harness 关闭、WSL、网络、特定发行版或临时 profile。

  **盘点记录（2026-10-31，对照 `.github/workflows/ci.yml` 与
  `test/probe/run-all-when-closed.sh`）：**

  - 调度：CI `probes` 任务仅在 `workflow_dispatch` 与 `schedule` 触发；
    push/PR 永不执行真机探针。
  - CI 覆盖缺口：任务只运行 6 项探针（`sandbox`（distro 内）、`mode`、
    `terminal`、`picker`、`missing-wsl`、`native-session`）；全套 15 项中的
    `sandbox-shell`、`interop-shell`、`sandbox-off`、`fs-routing`、`agent`、
    `watch`、`substrate`、`exec` 和 `run.sh`（`--include-fs`）不在 CI 里。
  - CI 跳过路径（均以绿色结束，job 状态不可区分）：`wsl.exe` 不在 PATH；
    `wsl.exe` 存在但默认 distro 无法启动（hosted runner 属此形态）；逐项
    跳过仅当 Harness 应用目录缺失时发生，输出一行 skip 文本后继续。
  - 本地全套脚本：逐项尝试、不区分 SKIP 状态——前置缺失表现为该探针自身
    失败或其内部文本；结尾只有 `done: N probes, M failures`，读者必须翻
    逐项日志才能把"缺前置"与"真失败"分开。`tasklist.exe` 不可达时整体
    abort（exit 1），不冒充结果。
  - 待设计（下一项）：四态（通过/失败/跳过/未运行）汇总需先有不依赖真机
    的测试，再改脚本或 CI。
- [ ] 设计结果汇总，分别显示通过、失败、跳过和未运行；缺前置条件时不得将套件报告为完整通过。先为汇总和失败路径增加不依赖真机的测试，再修改脚本或 CI。
- [ ] 若能提供专用 Windows + WSL + Harness 环境，先由维护者手动执行 `bash test/probe/run-all-when-closed.sh --include-fs`，保存经审阅脱敏的环境和结果，再考虑定时执行。
- [ ] 如使用自托管 runner，只允许可信分支的受控任务，限制凭据和网络权限；不让外部 PR 的任意代码自动进入个人开发机。runner 隔离和清理方案单独审查。
- [ ] 若专用环境暂不可用，保留人工发布门槛并明确显示“自动真机验证未配置”；不得以 hosted job 的跳过冒充真机通过。

**验收：** 至少一次受控真机记录包含版本、环境、各项实际结果及跳过原因；自动化配置的情况下，缺依赖、探针失败和完整通过均有可区分的状态。行为变更按发布流程执行完整真机套件。

## 工作项 4：安全边界与可理解性（P0）

**涉及：** `docs/CONFIGURATION.md`、`docs/LIMITATIONS.md`、`SECURITY.md`、`test/probe/interop-shell.sh`、`test/probe/interop-shell-probe.mjs`。

- [ ] 用三个场景说明：默认可见、遮罩 `/mnt`、发行版级禁用 interop；区分受限命令、受限写入、非受限读取和 Windows 宿主操作。
- [ ] 核对 `interopVisibility` 与 `maskWindowsDrive` 的优先级及各服务配置范围；示例说明遮罩可能影响 `/mnt/c` 项目和脚本，但不会删除文件。
- [ ] 引用现有探针说明已验证的范围，并明确其他挂载点及 interop 的限制；对真实安全边界的任何变更先写威胁模型、回滚方案及两条命令执行路径的测试。
- [ ] 这一步只改善说明和验证，不修改现有用户的默认配置，也不运行会重启或修改用户 WSL 的命令。

**验收：** 文档不声称 Linux 沙箱能完全阻止 Windows 访问；用户能辨认各选项的收益、兼容性代价及验证范围。

## 工作项 5：故障恢复与兼容性（P1）

**涉及：** `docs/LIMITATIONS.md`、`docs/COMPATIBILITY.md`、`docs/ROADMAP-1.0.md`、与复现故障直接相关的 `src/`、`test/` 和 `test/probe/` 文件。

- [ ] 按首用反馈与已有已知限制建立故障表，优先检查 agent 退出、发行版不可用、磁盘空间不足、升级中断和多发行版并发；每项先确认当前行为和复现条件。
- [ ] 对重现的问题补充回归测试，区分自动恢复、明确失败和结果未知；不得为隐藏错误而回退到无约束执行。
- [ ] 覆盖驻留和一次性命令路径；文件操作在 agent 不可用时保持失败关闭。涉及真实系统行为时补充适用真机探针。
- [ ] 更新兼容性记录，区分真实发行版、容器和 QEMU；物理 ARM WSL 或其他未执行的环境不得标记为实机通过。

**验收：** 每项已修复问题有复现、测试及可理解的用户反馈；剩余问题有影响范围和处理决定。性能或恢复时限只在足够的实测后承诺。

**涉及：** `docs/UPSTREAM-FILE-REFERENCE-SEAM.md`、`docs/UPSTREAM-SESSION-NOTICE.md`、`docs/upstream/`、`docs/PERFORMANCE.md`。

- [ ] 核对 `@` 引用、会话提示和其他上游接口的当前状态；每个提案准备影响、最小复现、所需接口和本插件在上游未合入时的行为。
- [ ] 优先提交边界清晰、用户影响明确的接口提案；上游未接受时继续标记为限制，不承诺上线日期。
- [ ] 在相同机器、同一项目和可重复条件下测量代表性工作流；分别报告插件方案与对照方案的环境、样本量、计时口径、分布及失败情况。
- [ ] 只有实测显示用户可感知的瓶颈时才实施性能优化；单个开发机数字不直接推广到所有机器。

**验收：** 至少一个高价值上游缺口具备可提交的材料；性能报告可复现，不把底层单项测试当成完整 GUI 体验。

- [ ] 核对安装入口与问题模板是否让用户快速找到版本、诊断和隐私提示；在相关社区分享前核对社区规则，不进行批量推广。

**验收：** 演示和入口中的安装方式与实际版本一致；反馈流程明确，指标有来源、口径与隐私边界，不根据代理指标宣称使用量第一。

## 发布评估与停止条件

- 每个独立变更先做适用的定向测试，合并前运行 `pnpm test`；需要覆盖率或发布时遵循 [发布流程](../../RELEASING.md)。行为变更运行适用的真机探针，并记录未执行项。
- 若发现安全边界被绕过、错误目录执行、数据丢失或用户配置不兼容，暂停新功能与宣传，先复现、缓解并确定修复及回归测试。
- 若缺干净环境、测试用户、runner 或上游配合，明确记为阻塞或未验证；不以模拟测试、人工推断或绿色跳过替代。
- 对 1.0 的决定沿用现有路线图和迁移/发布门槛，额外核对兼容性、未解决高优先级问题和文档一致性；不因计划周期结束自动发布。

## 建议的第一个执行批次

1. 完成工作项 1 的文档清单和现行入口审查，修正已确认的探针时效冲突。
2. 产出工作项 2 的首次安装记录表，确认是否有干净环境和志愿测试者。
3. 不等待外部测试，先完成工作项 3 的 CI 跳过路径盘点和结果设计；是否配置专用 runner 由维护者另行决定。

# 2026-11-19 HMR 更新门禁：rc.5 上的 Git 固定 commit 复验

2026-11-17 的记录在同一台机器上发现：Git 固定 commit 安装的 bundle 经
`pluginManager.updateBundle` 升级后，`dsh.profile.bundles` 丢失该 bundle，重启后
三个服务回到 shipped 实现（上游 discussion
[#13609](https://github.com/deepseek-ai/deepseek-harness/discussions/13609)）。
桌面端于 2026-11-18 更新到 0.2.2-rc.5；本文用同一对 commit 复验该结论。

## 环境

- 宿主 0.2.2-rc.5（`app.asar` 内的 `@deepseek-ai/dsh-plugin-manager` 同为
  0.2.2-rc.5），Node 24.21.0。
- 临时 `DSH_HOME`：`C:\Users\andyz\AppData\Local\Temp\dsh-hmr-gate7`，用
  `--from-default-profile web` 创建 `gate` profile；该模板包含 `hmr` 与
  `plugin-manager` 行。
- 插件 0.26.1，Git commit `525571f0c568b55b3e8657d0542264178aedc59f`；目标
  0.26.2，commit `65018178591b3bcc7fd22a966485e2838c22e0a9`。安装后
  `dsh.profile.bundles` 含该 bundle，`cordis.patch.yml` 为 `[]`。
- 探针行通过 `--patch` overlay 叠加，不放进插件 bundle；探针创建一个活动的
  `standard` 会话后在独立任务里调用更新。

## 方法

- 探针在 `ctx.inject(['hmr'])` 的子上下文里等 HMR 挂载后创建会话并调用
  `pluginManager.updateBundle("dsh-plugin-wsl-env", "0.26.2", { spec: <目标 commit> })`；
  `apply` 立即返回，更新放在定时器中，避免与 loader 重组互相等待。
- 同时轮询 profile 的 `package.json`（100 ms），记录每次 `bundles` /
  `dependencies` / 锁文件变化的边界状态。
- 更新后去掉探针重启，`verify` 模式只读 `subprocess` / `fs` /
  `directoryPicker` 的实现类。
- 第一次尝试使用默认 `githubConnectionTimeoutMs: 5000`，在更新前的 GitHub
  连接检查处失败；重跑时通过 overlay 把该值调到 30000。该配置只影响连接检查，
  不参与选择写入。

## 结果

```
update from=0.26.1 to=0.26.2 step=install
result application=applied changed=true stage=enable error=null
restore=null
providers-now={"subprocess":"WslSubprocessRuntime","fs":"WslRoutingFileSystem","directoryPicker":"WslDirectoryPicker"}
UPDATE OK
```

manifest 快照捕获的边界（省略 base / web-app 前缀）：

```
[1] bundles=[..., dsh-plugin-wsl-env] dependencies=...525571f
[3] bundles=[base, web-app]                       # remove 已丢弃选择
[4] dependencies=(none)                           # 依赖已移除
[5] dependencies=...6501817                       # 目标版本安装
[6] bundles=[..., dsh-plugin-wsl-env]             # install 后选择写回
[7] lock=false                                    # 更新结束
```

更新后的 `package.json` 同时保留 bundle 与目标 commit 依赖；`cordis.patch.yml`
仍为 `[]`。重启验证：

```
HMRPROBE providers={"subprocess":"WslSubprocessRuntime","fs":"WslRoutingFileSystem","directoryPicker":"WslDirectoryPicker"}
HMRPROBE VERIFY OK
```

第一次尝试（默认 5 秒连接检查）：

```
HMRPROBE update from=0.26.1 to=0.26.2 step=check
HMRPROBE result application=failed changed=false stage=install error=operation-error
HMRPROBE diagnostic=fatal: unable to access 'https://github.com/Big-Dao/dsh-plugin-wsl-env/':
  TLS connect error: error:0A000126:SSL routines::unexpected eof while reading
dsh: connection to github.com timed out after 5000ms
```

这次失败发生在 `step=check`，没有移除 bundle，profile 未改变。

## 结论

- 在 rc.5、同一对 commit、同样的 headless web composition 下，Git 固定 commit
  更新不再丢失 bundle 选择：选择在 remove 时按预期移除，install 后写回，重启
  后三个服务仍由本插件提供。问题无法复现。
- 2026-11-17 的 rc.3 记录仍是当时的事实；本文不能判定它是在 rc.4/rc.5 中被
  修复，还是依赖了本次没有重现的运行条件。
- GitHub 连接检查的 5 秒上限会让该更新在慢连接上呈现为 `step=check` 失败；
  它与选择丢失无关，但复验时应单独排除。
